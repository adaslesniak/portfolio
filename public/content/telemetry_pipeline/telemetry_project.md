# Data Pipeline Refactor

In **May 2025**, I undertook a major refactor of a legacy data pipeline that had slowed down development for months.  
The goal was simple: **reduce technical debt so the project could move forward again**.

---

## Background

The existing pipeline had grown organically over several years:

- Multiple inconsistent ETL scripts.
- Weak test coverage.
- No clear ownership of preprocessing logic.
- Poor observability.

This made even small changes risky and time-consuming.

---

## My Contribution

- **Refactored** the entire preprocessing flow into clear, modular stages.
- **Added automated tests** for each stage.
- **Introduced WPF tooling** so analysts could visualize intermediate data.
- **Standardized logging** for better debugging.
